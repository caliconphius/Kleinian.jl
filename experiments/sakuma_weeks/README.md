# Sakuma–Weeks experiments

A focused workspace for extracting the calculations in `../farey-testing/`
and connecting them to Farey, Kleinian and Poincare. The source notebooks remain
unchanged. This module has no plotting side effects or dependence on REPL globals.

## Start here

From the repository root (run `julia experiments/setup.jl` first if needed):

```sh
julia --project=experiments experiments/sakuma_weeks/interactive.jl
julia --project=experiments experiments/sakuma_weeks/runtests.jl
julia --project=experiments experiments/sakuma_weeks/render.jl
```

The interactive example starts at slope `2//5`. Change that argument to `3//8`,
`5//12` or `10//33`. Controls select the geometric model, how many tetrahedron
pairs are shown, and a transformation of the entire developed domain. The static
renderer writes `sakuma_weeks_10_33.png` beside these files.

```julia
include("experiments/sakuma_weeks/SakumaWeeks.jl")
using .SakumaWeeks
s = PolynomialSystem()
Qpoly(s, 2//5)                    # x^2 - x + 1
z = geometric_root(s, 2//5)        # exact algebraic root
D = developed_domain(s, 2//5)      # two Poincare tetrahedra
# An incomplete deformation with positive shapes:
D2 = developed_domain(s, 10//33; parameter=0.45+0.28im)
```

`D.triples` and `D.shapes` retain exact algebraic values when the parameter is
exact. `D.tetrahedra` uses Float64 ideal-point coordinates for plotting. `complete`
records exact vanishing of Q at the supplied parameter; it is not an independent
face-gluing or completeness certificate. Approximate roots may give `false`.

## Source and conventions

Reference: Eric Chesebro, [*Geometry for Kleinian Groups Generated by a Parabolic
Pair*, arXiv:2512.17044v1](https://arxiv.org/html/2512.17044v1).
The notebook formulas match this paper. Relevant locations are Examples 3.8–3.9,
Definition 4.17, Definitions 5.1–5.2 and 5.8, and Definition 5.18.

The paper's parameter is `x`; our existing Riley API uses `rho`. The canonical
pair in §5.3 is `U₀⁻¹, W₀`, corresponding to `rileygroup(-1/x)`. The introductory
pair instead uses `+1/x`, obtained by inverting the second generator. Keep this
choice explicit when comparing figures. `boundary_isometry(A)` conjugates a
boundary-action matrix before passing it to Kleinian's spinor convention.

Geometric roots are selected with exact Nemo algebraic arithmetic, testing every
interior shape for positive imaginary part. Reciprocal slopes `1/n` are excluded
from this root selector. Poles and flat/inverted layers are rejected. A unique
root is required instead of silently choosing the first candidate.

## What this implements, and what comes next

The new code develops the tetrahedron pairs from the paper's coordinates,
renders them, and applies isometries. It does **not** yet construct a face-paired
`Poincare.TetrahedralComplex`. Transform controls move the whole domain; they do
not perform a triangulation flip or Pachner move.

Next steps:

1. Attach the rational edge labels to every tetrahedron and derive explicit
   layer-to-layer face permutations.
2. Implement the top and bottom folds and their isometries; verify edge-cycle
   products and cusp completeness separately.
3. Use those checked pairings to show adjacent domain copies, paired-face
   highlights and animated layer transformations.
4. Add parameter deformation controls with diagnostics for poles and flattening;
   only then broaden to cusp/Heckoid examples and changes of triangulation.

The current checks compare small explicit polynomials, two independent shape
formulas, known roots, geometric tetrahedron shapes and Möbius actions. They do
not certify an arbitrary quotient or a global tessellation.
